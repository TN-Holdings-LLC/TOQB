## 背景（職場の数字、TOQB `notes/hubbard_2026-11-11/`）

**回路：** 1次元ハバード模型の時間発展（L サイト、2L 量子ビット、フェルミオンの入れ替えを使う1次のトロッター分解）
- 1ステップあたり CZ 10L−8、CZ 12層

**実機で読めそうな範囲：** 実機の記録から見て、4〜6ステップ（Jt 1.0〜1.5）。

**古典での検算の費用：** 職場の2コアでは次のとおりでした。
- 厳密対角化は、L=20 で 546 GB 要る
- Aer の MPS は、L=20 の 4ステップで120秒。6ステップは27分たっても終わらなかった

この先、検算がどこまで届くかで、宣言に入れる大きさが決まります。

## 何を測るか

| 項目 | 範囲 |
|---|---|
| 大きさ | L = 20、24、30（40、48、60 量子ビット） |
| ステップ | 4、6、8（Jt 1.0、1.5、2.0） |
| 方法1 | Aer の MPS。切り捨てなし（終われば基準になる） |
| 方法2 | quimb の CircuitMPS。結合次元の上限 χ = 256、512、1024、2048。切り捨てた重み（error_estimate）も記録する |
| 1件の上限 | 2時間 |

1件ごとに、次の値を記録します（`hub_cost.py` が自動で書き出します）。
- 時間、メモリ、実際の最大の結合次元、切り捨ての見積もり
- 保存量の確認：<Z> の和（0 のはず）と、上向きと下向きの差（0 のはず）
- 同じ (L, ステップ) の他の結果との、モードごとの <Z> の最大の差

## 「検算できた」の目安（計算の前、02:13 CET に固定。結果を見て変えない）

ある (L, ステップ) を「検算できた」と言うのは、次のどちらかが成り立つときです。

1. Aer の切り捨てなしが2時間以内に終わり、quimb の最大の χ との差が 1e-3 以下
2. quimb の、隣り合う2つの χ（例：1024 と 2048）の差が 1e-3 以下で、大きい方の χ の切り捨ての見積もりが 1e-4 以下、保存量の確認の絶対値が 1e-3 以下

## 手順

1. zip の sha256 を、別の「VS クロードへ」のファイルに書いた値と照らし合わせる。
2. CPU の POD を借りる。目安は 32 vCPU・メモリ 128 GB 以上を2台か、16 vCPU を4台。GPU は不要。
3. 大きさとステップで分けて、各 POD で次のように流す。
   - 例：POD 1 で `bash run_pod.sh "20" "4 6 8" "256 512 1024 2048" P1`
   - L=24 と L=30 も、同じように別の POD に割り当てる。
   - 安いものから流す作りになっています（同じ L とステップでは、quimb を χ の小さい順に、そのあと Aer）。
   - 2時間で止まった件は、報告に「stopped」として残ります。
4. 持ち帰るもの：各 POD の `*_report.jsonl` と、`run_pod.sh` の画面の出力（バージョン、コア数、時刻、値のファイルの sha256）。
5. **POD は全部削除する。**
