# 指示書：SPD（疎なパウリ動力学）を小さい δ で回す POD — VS Code の Claude へ（職場クロード、2026-11-04）

**実行は、在庫の POD（bank_2026-11-04）が終わってからにしてください。** CPU だけで足ります（GPU は要りません）。結果の解釈はせず、出力をそのまま持ち帰ってください。宣言の対象ではありません。

## 1. 何をするか

`rust/spd`（Rust、外部 crate なし）を、職場の 2 コアでは回せない小さい δ（3e-5、1e-5、P6 は 1e-5、3e-6）で回します。

- **P5（kingston の格子 b、151 量子ビット）：** t = 6〜8 の封印済みの答えとの照合と、t = 20 の全量子ビット。
- **P6（Qedma の 35 量子ビット）：** t = 6〜9 の封印済みの答えとの照合。

## 2. POD の選び方

- CPU のコア数が多く、**メモリが多いもの**。目安は 32 コア以上、メモリ 256 GB 以上です。1 スレッドあたり約 8 GB 使うので、スレッド数は「コア数」と「メモリ GB ÷ 8」の小さいほうに自動で決まります。
- 項数が 6,000 万（約 8 GB）を超えた量子ビットは計算を打ち切り、「capped」と記録されます（エラーにはなりません）。
- 費用の上限は持ち主の指示に従ってください。目安：P5 の t = 20、δ 1e-5 は、職場の 2 コアの実測から数十〜数百コア時間と見込んでいます（未確認）。
- 安全装置として、4〜8 時間で POD を止める待機処理を置いてください（いつもどおり、キットの外に）。

## 3. 手順

```bash
# TOQB at the commit given in the hand-over (c1a1353 or later with rust/spd and notes/spd_2026-11-04), psf-os 61e9edd or later
export OUT=/workspace/spd PSFOS=/workspace/psf-os
bash TOQB/notes/spd_2026-11-04/spd_pod.sh > /workspace/spd_run.txt 2>&1
```

- 最初に `cargo test --release` が通ること（6 本）を確かめてから計算に入ります。Rust がなければスクリプトが入れます。
- 3 つの段（P5 の t = 6〜8、P5 の t = 20、P6）を順に回します。途中で止まったら、そこまでの JSONL を持ち帰ってください（1 行が 1 つの組み合わせで、追記型です）。

## 4. 持ち帰るもの

- `$OUT/` 一式：`times.txt`、`log.txt`、`spd_t678_small.jsonl`、`spd_t20_small.jsonl`、`spd_p6_small.jsonl`。
- `/workspace/spd_run.txt`。
- POD の種類、コア数、メモリ、開始・終了時刻（CET）、費用を、報告に書いてください。
