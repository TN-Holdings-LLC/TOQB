## 書式の要点（詳しくは docs/card.md）

```json
{"card": 1, "name": "...",
 "lattice": {"kind": "chain|grid2d|grid3d", "size": [...]}  または  {"kind": "graph", "sites": n, "edges": [[a,b],...]},
 "hamiltonian": {"terms": [{"pauli": "ZZ", "sites": [a,b] | "on": "edges"(+"axis") | "on": "sites", "coef": 実数, "group": "g"}]},
 "initial": {"bits": "0101..."} または {"product": "+r-l..."},
 "time": {"dt": ..., "steps": ..., "order": [グループ名...]}  または  "orders": [[...],[...]]（ステップごとに巡回）,
 "measure": [{"op": "Z", "sites": "all"}, {"op": "ZZ", "sites": [i,j]}, {"op": "X", "sites": [i]}],
 "conserved": [{"name": "...", "terms": [...]}]}
```

- **格子：** 格子の上のサイトの番号は itertools.product の順で、psf_os.grid3d と同じです。
- **時間発展：** 1ステップは、順序どおりの各グループについて exp(−i·dt·c·P) を項ごとにかけます。1つのグループの中の項は可換でなければならないので、グループの中の順序は答えに効きません。
- **分解（決まった形で、探しません）：**
  - 1サイトの項：RX、RY、RZ
  - 2サイトの項：各量子ビットを Z に回し（X は H、Y は S† H）、exp(−i·a·ZZ) をかけて戻します。
  - exp(−i·a·ZZ) は H·CZ·RX(2a)·CZ·H で、CZ 2個です。a = ±π/4 のときは CZ 1個と RZ で書きます。
  - 置き方はしません。
- **読む基底：** 測る量から決まります。各量を、文字が食い違わない最初の設定に入れます。Z だけのカードは1つの設定で読めます。
- **厳密な答え：** カードの Trotter 回路そのものの期待値で、exp(−iHt) の答えではありません。
  - 20 サイトまでは Statevector、21〜28 サイトは Aer の save_expectation_value を使います。
  - 21 サイトの鎖で2つの方法を比べ、差は 1.8e-13 でした。時間は Aer が 2.7 秒、Statevector が 65 秒です（`outputs/aer_check.txt`）。

## 受け口の検査で止まる例（出力の全文、終了コード 2）

```
$ python -m psf_os.card check examples/cards/refused_example.json
REFUSED
  - size: 32 sites; exact answers by statevector only up to 28
  - hamiltonian term 2: ZZ on sites [0, 3] is not on an edge of the lattice
  - hamiltonian term 3: coefficient '0.2+0.1j' is not a real number (H must be Hermitian)
  - group 'zz': terms ZZ[0, 8] and X[0] do not commute (a group's terms must commute)
  - time.order: unknown group(s) ['y']
  - initial: bits must be a string of 32 characters 0/1 (character i = site i)

$ python -m psf_os.card check examples/cards/refused_conserved.json
REFUSED
  - conserved 'total X': does not commute with H (largest coefficient of [H, Q] 2)
```

保存量の検査は、ほかに止まる理由がないときに行います。H と交換するときは、各グループが保存量を保つかどうか（Trotter 回路で厳密に保たれるか）も報告します。たとえば XX+YY の鎖の全 Z は、H とは交換しますが、XX のグループと YY のグループはそれぞれ保ちません。

## 受け入れの結果

### A. kicked Ising 4×2×2、θ 0.6

カードでは dt = 1、ZZ の係数を −π/4（RZZ(−π/2) = exp(+iπ/4·ZZ)）、X の係数を θ/2 としました。t 1〜4 のどれも一致しました（最大 1.4e-13）。

### B. Heisenberg XXX 4×2×2、dt 0.05、Néel（heisE と同じ）

heis3d の厳密な答えは、置き方が結合をかける順序で決まります。そこで2通り確かめました。

- **B1：教科書の順序。** 結合を、軸と偶奇で6つの可換なグループに分けました。heis3d.exact_from_log に同じ順序の記録を渡した答えと、t 1〜4 で一致しました。
- **B2：heisE の実際の順序。** 11-08 の ibm_kingston の記録から、heis3d_build と同じやり方で候補4つを作りました（r0/c0 は 1/0、1/4、1/8、3/0）。
  - old、carry、line の結合の記録を、1結合1グループ、ステップごとの順序 `orders` としてカードにしました。
  - 48通りすべてで、heis3d.exact_from_log とも、公開済みの表 heis_answers_Ek.json とも一致しました（最大 1.2e-13）。

### C. シュウィンガー N=6、M1、dt 0.25

- 格子は `graph` で、15組すべてのサイトの対を辺にしました。
- 項は Z が6、ZZ は A が 0 でないもの、ホッピングの XX と YY です。
- swap network の各層を1つのグループにしました。層の中の対は重ならないので、可換です。
- 順序は、奇数ステップが [z, 層1..6]、偶数ステップが [z, 層6..1] です。

1・2 ステップとも一致しました（最大 2.3e-14）。

## 足りない点

1. **順序が1つだけでは足りません。** 置き方やネットワークによっては、ステップごとに順序が変わります。ステップ1の順序を全ステップに使うと、次の差が出ました。
   - heisE：t ≥ 2 で 8.8e-3〜2.2e-2（3方式とも、記録の中の順序は2通りの繰り返し）
   - シュウィンガー：2ステップで 5.4e-2（偶数ステップで層を逆に回すため）

   キットの書式（「1次の分け方は項のグループの順で書く」）を広げ、`orders`（ステップごとの順序のリストを巡回して使う）を足しました。これは書式に足した点として報告します。
2. **順序は問題ではなく置き方のものです。** heisE の答えは、置き方が結合をかける順序で決まります。そのため、置く前に書いたカードでは、実機の回路と同じ答えは出ません。今回は、heis3d が残す結合の記録からカードを作りました。置き方が自分の順序をカードの形（`orders`）で返す仕組みが要ります。
3. **遠くまで届く結合。** シュウィンガーの ZZ はすべての対にかかるので、`chain` では書けず、全部の対を辺にした `graph` で書きました。この場合「項が辺の上にあるか」の検査は形だけになります。置くには swap network のような経路が要りますが、カードはそれを持ちません。
4. **kicked Ising はハミルトニアンの時間発展ではなく、蹴りの繰り返しです。** dt = 1 として、角度を係数に入れて書きました。答えは一致しますが、`dt` が物理の時間を表さなくなります。
5. **CZ の数が多くなります。** 分解は項ごとに決まった形なので、次のようになります。
   - Heisenberg：1結合あたり CZ 6個で、1ステップ 168 個です。heis3d の1結合の塊は KAK で最大 3 個です。
   - シュウィンガー：経路なしで1ステップ 40 個です。schwinger.py は経路込みで CX 45 個です。
   - kicked Ising：28 個で、CZ 1個の形になります。

   1つのグループの中で同じ対にかかる可換な項を、1つの2量子ビットの塊にまとめるのが次の手です。まとめても答えは変わりません。
6. **そのほか：**
   - 定数項（恒等演算子の倍）は大域位相なので書きません。
   - 読む基底の分け方は貪欲法で、設定の数が最小とは限りません。
   - 宣言した保存量について、Trotter 回路で保たれるかどうかは報告するだけで、止める理由にはしていません。
