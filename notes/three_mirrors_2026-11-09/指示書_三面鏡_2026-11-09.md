# VS Claude へ：三面鏡の試作を POD で（2026-11-09、職場の Claude より）

オーナーの許可：「POD 借りて64コアで即計算を VS クロードに頼んでもよい」。シミュレータだけの計算です。IBM・GitHub・実機にはつながないでください。

## 何をするか

三面鏡（オーナーの発想）を試作し、シミュレータで確かめます。1つの配置について、次の4本の回路の「格子点の平均 <Z>」を比べます（理想はどれも +1）。

- **正面 F：** 今の往復（コンパイルした U・バリア・U†）
- **左 L：** U のうち橋げたに触れない命令だけの往復（x・z の結合、入れ替え、RX）
- **右 Rt：** U のうち橋げたに触れる命令だけの往復（y の結合）
- **R：** 読み出しだけの回路

部分どうしの誤りが独立なら F·R ≈ L·Rt になるはずです。そこで delta = F − L·Rt/R を見ます。delta が 0 からずれれば、部分どうしが影響し合っている（クロストークなど）ことになります。

## 合格の目安（計算の前、2026-11-09 01:39 CET に固定済み。`three_mirrors.py` の冒頭）

- C1：ゲートごとの雑音だけ（cz・sx・x の脱分極）なら |delta| ≤ 2SE
- C2：結合した量子ビットの間に常に ZZ がある場合（仮定として値を固定、ζ rad / CZ 層、雑音なしのユニタリ）、ζ = 0.02 で delta < 0 が 2SE を超える
- C3：実機で、ζ = 0.02 の delta を 2SE で見分けるのに必要な時間が、今の1配置（3回路 × 4000 ショット）の 1.5倍以内（ショット雑音の見積もりは職場で行うので、POD では不要）

## 手順

1. POD（64コア、CPU だけで足ります）を借りる
2. このフォルダを POD に上げて `bash run_pod.sh`
   - psf-os はバンドルの 0fb4512 を使います（grid3d の layout "line" 入り）
   - 計算の範囲：line と fold、4×2×2、θ 0.6、t1〜4、ζ 0 / 0.005 / 0.01 / 0.02、2000 軌道
   - 器の記録は fez 11-08（`dev/device.json`、故障の一覧と結合だけ）
3. `three_mirrors_pod.json` と `three_mirrors_pod.txt` を持ち帰り、ZIP にしてデスクトップの psf_zero_project に置く
4. POD は削除する。使った時間と費用を一行で書く

## 見積もり

職場の2コアでの計り方から、64コアで30〜50分程度、費用は数ドルの見込みです。1時間半を超えそうなら、t を 1〜3 に減らしてください。
