## 範囲を変えたか、直した箇所

- **範囲は変えていない。** line と fold、4×2×2、θ 0.6、t 1〜4、ζ 0 / 0.005 / 0.01 / 0.02、2000 軌道（100 軌道 × 20 かたまり）。
- **上限の1時間半を超えた（約2時間50分）。** 途中で回路ごとに10軌道だけ実測し、見込みが約2時間を超えることがわかった（ζ > 0 の回路は ζ = 0 の 8〜12 倍かかる）。オーナーに確かめたうえで、`--ts 1,2,3` に減らさずに最後まで流した。
- **4台に分けた。** 同じコマンドで、`--layouts` と `--ts` だけを分けた（`parts/run_pod_split.sh`。`run_pod.sh` の複製で、この2つを引数にしただけ）。乱数の種はかたまりの番号だけで決まる（`1000*i+11`）ので、値は1台で全範囲を流したときと同じになる。4台の結果は値を変えずに並べ直し、1つにまとめた（`three_mirrors_pod.json` / `.txt`）。それぞれの POD の出力は `parts/` にある。
- **venv を使った。** イメージの Python が pip を受けつけなかった（PEP 668、externally-managed-environment）。そこで `python3 -m venv` で作った venv を PATH の先頭に置いて流した（`parts/go.sh`）。スクリプトは直していない。
- 見積もりのため、A と C で `parts/est.py`（同じ回路を10軌道だけ流して時間を測る）を数分走らせた。本計算の値には関わらない。
