# Heisenberg 4×2×2：運ぶための CZ を減らす（2026-11-08、VSクロードより）

これは宣言していない検討の記録です。IBM と GitHub にはつないでいません。TOQB と psf-os は読んだだけで、変えていません。計算はすべて手元の WSL の CPU で行い、POD と 4070 は使っていません。

## 出発点（TOQB 7ecb52c、`heis3d --carry`）

1ステップ152 CZ の内訳です。

- 結合：28本 × 3 = 84
  - x 方向：12本
  - z 方向：8本
  - y 方向：8本
- 空の入れ替え：4つの行ブロック × 3回 × 3 = 36
- 橋げたへの出し入れ：y 方向の結合8本 × 4 CX = 32

## 1. 空の入れ替え 36

**今の枠組みでは、36が下限です。**

- z 方向の結合は、ブロックの境目（位置3）でしかできません。なので1ステップのうちに、4つの列すべてが位置3を通る必要があります。
- 位置3まで動く距離の合計は、並び方によらず 0+1+2+3 = 6 です。入れ替え1回で、右へ1つ動けるのは1つの列だけです。
- そのため、1つの行ブロックにつき入れ替えは6回以上必要です。そのうち相乗りできる x 方向の結合は3本しかないので、空の入れ替えは3回以上になり、合計は36以上です。
- 総当たりでも確かめました（`ladder_bfs.py`）。8量子ビットの線で、今の並べ方から始めると最少6回でした。ブロックの境目をまたぐ入れ替えを許しても6回のままでした。

**枠組みを変えると、0回にできます**（`ladder_bits.py`、結果は `ladder_bits_result.txt`）。

- 変えるのは3点です。
  - 始まりの並べ方を自由に選ぶ。
  - z 方向の結合も、境目をまたぐ入れ替えに SWAP·U として相乗りさせる。
  - 8つの格子点のすべてが、一度は橋げたの位置を通ることを条件に加える（y 方向の結合のため）。
- 探索は、状態（並べ方 × 結合10ビット × 橋げた訪問8ビット）をビット集合で数え上げる総当たりです。
- 結果は次のとおりです。

| 橋げたの位置 | 空の入れ替えの最少回数（1本の線あたり） |
|---|---|
| 1 と 5（heavy-hex の奇数行） | **0回** |
| 3 と 7（偶数行） | 2回 |

- 橋げたが位置1と5の場合の手順です。線の位置は0〜7で、k' はブロック z=1 の列 k を表します。

```
始まり: 0' 1 0 1' 2' 3 2 3'
SWAP.U(3,2)@5 ; SWAP.U(3,3')@6 ; U(1',2')@3 ; SWAP.U(2',2)@4 ; SWAP.U(2',3')@5 ;
SWAP.U(1,0)@1 ; SWAP.U(1,1')@2 ; U(1,2)@3 ; SWAP.U(0',0)@0 ; SWAP.U(0',1')@1
終わり: 0 1' 0' 1 2 3' 2' 3
```

- 2本の線（y=0 と y=1）は、同じ手順を同時に流します。
- 格子点が橋げたの位置に来たら、その場で y 方向の結合を入れます（今と同じく、移す2 + 結合3 + 戻す2）。
- 偶数ステップは、同じ手順を逆向きに流します。U は2つの量子ビットを入れ替えても同じなので、SWAP·U を逆向きに流しても SWAP·U のままです。

## 2. 橋げたへの出し入れ 32

- 調べたのは、橋げた b が |0> で始まって |0> で終わる条件で、a–b–q の経路を使って U(a,q) を作るのに CZ が最少何個要るかです。
- CZ の並べ方（ab と bq の並び）を総当たりし、各並べ方で1量子ビットの回転を最適化しました。12回ずつ乱数で始め、dt = 0.3 で試しました（`bridge_min.py`、結果は `bridge_min_result.txt`）。

| CZ の数 | 最良の誤差 |
|---|---|
| 今の作り方（7） | 1.2e-9（できる。最適化のやり方が正しいことの確認） |
| 5 | 8.7e-2（できない） |
| 6 | 4.5e-2（できない） |

- 7より少なくはできない、と数値からは見えます。数値の上での判断で、証明ではありません。
- 別の形で減らせる部分があります。ステップの境目で、同じ格子点が橋げたの位置にいることがあります（逆向きに流すので必ず起きます）。このとき「戻す → 移す」が打ち消し合い、続けて入る同じ U(dt)·U(dt) は、1つのブロック（3 CZ）にまとまります。
  - 回路そのものも、Trotter 積も変わりません。
  - 記録には結合が2回入っているので、正解の計算は今のままで合います。

## 3. 確かめたこと（`verify_line.py`、`run_verify.sh`）

- 18量子ビットの抽象的なグラフ（2本の8量子ビットの線と、橋げた2つ）の上に回路を組みました。
- CZ は、合成したあとの数です（basis cz/rz/sx/x）。
- 雑音なしで、配置した <Z> と、記録した結合の順番どおりの厳密な Trotter 積を比べました（dt 0.05）。

| 方式 | t=1 | t=2 | t=3 | t=4 | 配置 − 厳密 | 橋げた |
|---|---|---|---|---|---|---|
| 宣言した方式（11-07） | 176 | 348 | 520 | 692 | – | – |
| carry（7ecb52c） | 152 | 304 | 456 | 608 | – | – |
| 新方式・位置1と5、opt 1 | 116 | 224 | 332 | 440 | ≤ 3.3e-16 | |0> に戻る |
| **新方式・位置1と5、opt 3** | **116** | **212** | **308** | **404** | ≤ 3.3e-16 | |0> に戻る |
| 新方式・位置3と7、opt 1 | 128 | 248 | 368 | 488 | ≤ 3.3e-16 | |0> に戻る |

- 新方式での正解の m_s は 0.9313 / 0.7571 / 0.5295 / 0.3037 でした。結合の順番が変わるので、宣言した値（0.9316 / 0.7568 / 0.5302 / 0.3078）とは少し違います。
- t=4 では、CZ が 608 → 404 に減ります（約34%減）。
