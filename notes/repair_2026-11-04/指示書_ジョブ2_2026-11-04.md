# 指示書：今夜、OS2D の結果から鎖を動かしてジョブ2を作り、送る（家の Claude 向け、2026-11-04）

決定済みの条件（オーナー、08:24 CET）は次のとおり。

- 確かめる規則は (b)、戻し方は期限（7日）。
- 今夜の OS2D のジョブをジョブ1として使う。
- 閾値（0.8 / 1.25）だけは今夜の結果を見て決める。

使うもの：psf-os 1250c90、TOQB（このコミット）、P6 の答え `results/p6-answers-2026-11-04/answers_cpu.json`（封済み）。

以下では、OS2D の出力フォルダを `OS2D=results/os2d-2026-11-04` と書きます。実際の名前に読み替えてください。中に `V/job`（manifest.json、submission.json、raw_counts.json）と `V/runs` がある前提です。

## 0. 準備

```bash
export PYTHONPATH=<psf-os>:<TOQB>
OS2D=results/os2d-2026-11-04
OUT=results/repair-2026-11-04
mkdir -p $OUT
```

## 1. OS2D の結果を台帳にする（ジョブ1の読み）

```bash
python notes/repair_2026-11-04/ledger_from_job.py $OS2D/V/job $OS2D/V/runs none $OUT/ledger_after_os2d.json os2d auto
```

- 入力：OS2D の `V/job`（raw_counts.json と submission.json が要る）と `V/runs`。
- 入力の台帳は `none` にする。この試験の台帳はジョブ1の読みだけで作る（下書き §3）。11/3 の読みは使わない。
- `auto` は、submission.json の CET 時刻を読む指定。
- 出力：`$OUT/ledger_after_os2d.json`。画面には床と往復の DEAD の量子ビットが出る。

## 2. 同じ機種を取り直し、鎖を動かしてジョブ2を組む

1. P6・OS2D と同じ取得手順で、**OS2D と同じ機種**を取り直す（fetch.json と target.pkl があるフォルダ）。これを `FETCH` とする。
2. 登録簿は、OS2D の `build.json` の `registry` にあるファイルを使う。これを `REG` とする。
3. 次を実行する。

```bash
python gpu/repair_job2.py $FETCH $REG $OUT/ledger_after_os2d.json b expiry $OUT/job2
```

出力：

| ファイル | 中身 |
|---|---|
| `$OUT/job2/chain.json` | 鎖の記録：外したものと理由、A と B の写し、見送った写しと理由、代償、台帳の SHA-256 |
| `$OUT/job2/build.json` | 組み立ての記録 |
| `$OUT/job2/V/runs` と `$OUT/job2/V/job` | 送るジョブ。18 回路、約 23 s |

状態によって、次のように進める。

- **`status TESTABLE`**：ジョブ2ができた。3 に進む。
- **`NOT TESTED (A and B on the same copy)`**：ジョブ1で DEAD が出なかった。ジョブ2は組まれない。chain.json を残して、結果「NOT TESTED」として報告する。**送るものはない。**
- **`NO COPY (B)`**：外した結果、置ける写しがなかった。同じく chain.json を残して報告する。送るものはない。
- **`NO COPY (A)`**：取り直した時点で、鎖を使わなくても置ける写しがない（故障の印が増えた）。送らずに報告する。
- TESTABLE でも、chain.json の A の写しが OS2D の写し（OS2D の build.json の `copy`）と違うことがある（故障の印が変わった場合）。
  そのときは実行間の揺れが出せず、判定はショットの SE だけで行う。報告にそう書く。
- **`STOP: ...`** と出たら、送らずに職場に連絡する。STOP の種類は次の 3 つ。
  - `the ledger has no readings for <機種>`：取り直した機種が OS2D と違う。
  - `readings after now`：時刻の取り違え。
  - `<OUT> exists`：同じ名前の出力フォルダが既にある（上書きしない）。

## 3. 送る前に記録する

1. 次の 4 つの SHA-256 を記録して、TOQB にコミットする。宣言の確定と同じ扱い。
   - `$OUT/ledger_after_os2d.json`
   - `$OUT/job2/chain.json`
   - `$OUT/job2/V/job/circuits.qpy`
   - 使った `REG`
2. その後、OS2D と同じ送信手順で `$OUT/job2/V/job` を送る（"stay"、緩和なし、4000 shots）。
3. ジョブ1との間隔は、両方の submission.json の時刻から報告する。

## 4. 結果が戻ったら

```bash
python notes/repair_2026-11-04/repair_score.py $OS2D/V/job $OS2D/V/runs $OUT/job2/V/job $OUT/job2/V/runs \
    $OUT/job2/chain.json results/p6-answers-2026-11-04/answers_cpu.json $OUT/repair_score.json
python notes/repair_2026-11-04/ledger_from_job.py $OUT/job2/V/job $OUT/job2/V/runs $OUT/ledger_after_os2d.json \
    $OUT/ledger_after_job2.json repair_job2 auto
```

1 本目（repair_score.py）の出力 `$OUT/repair_score.json` には次が入る。

- A と B の MSE、比 B / A
- ショットの SE（ブートストラップ、200 回、seed 0）
- 実行間の揺れ：OS2D と同じ写しなら |MSE_A1 − MSE_A2| / √2
- 代償
- 旗の寿命：外した量子ビットを、ジョブ2の A の床で読んだ結果

画面に出る判定は 0.8 / 1.25 で出した仮のものです。**閾値はオーナーが今夜決めます。**

2 本目（ledger_from_job.py）は、ジョブ2の床（A と B）を足した新しい台帳を書きます。古い台帳はそのまま残ります。
