# Pre-registration: TOQB loop long run, 6 qubits, 8 layers, 5 seeds x 100,000 iterations (2026-10-15)

**Status: pre-registration.** It is fixed by the commit that adds it (2026-10-15, about 18:20 CEST), with the plans,
the code hash list and the scoring script. That commit is pushed before the run starts. The run is made once. Times
are given in CEST.

## 1. The question

Does the difference between the compilers compound over a long training?

Runs 1 and 2 trained for 60 and 200 iterations. This run trains five models per compiler for 100,000 iterations,
with the settings of run 1 unchanged. It records the difference along the way.

## 2. What is run

**The plans:** [`loop-n6-long-2026-10-15/plan_s3001.json`](loop-n6-long-2026-10-15/) to `plan_s3005.json`, from
`make_plans.py`. `SHA256SUMS` has SHA-256 `cae9f0e3b0667dd6183e3a72dfe1e3aca5cca104df8f1ec4d1cf66b951403e50`.

**The same as run 1:**

- the task: n = 6, L = 8, teacher seed 4, 64 training and 48 test points;
- SPSA: batch 8, a = 3.0, c = 0.2, A = 2, initial angles in +-0.5;
- 400 shots; FakeFez with TOQB's noise model;
- the two arms, Qiskit level 2's template and PSF-Zero's template (a22 + c61, the same files and SHA-256 as runs 1
  and 2).

**What changes:**

- **Iterations:** 100,000. SPSA's step shrinks as (k + 3)^-0.602, so by the end it is about 1/1,000 of the first.
- **Evaluations:** at iterations 0, 20, 40, 60, 100, 200, 300, 600, 1,000, 2,000, 3,000 and 6,000, and every 10,000.
  Each evaluation is also written as it happens (`*.partial.json`).
- **The loss curve:** every 100th iteration.
- **The engine:** the fast engine (`toqb.fast_noise`), as in run 2.
- **Loop seeds:** 3001-3005.

**Code:** `CODE_SHA256SUMS` lists the nine modules (SHA-256 `6fad9ba8...1a81`).

- The modules changed since run 2 only for the long run: evaluation points, the thinned curve, partial records, and
  the SPSA draws kept as compact arrays (the same draws; checked).
- The fast engine skips a second scan of each circuit and moves fewer array axes. It gives the same p1 to 3e-15, and
  its tests pass.

**The machine and the command:**

- the owner's home PC (WSL), ten processes at a time (5 seeds x 2 arms);
- [`run.sh`](loop-n6-long-2026-10-15/run.sh), which checks every hash and the versions.
- **Expected time:** about 0.19 s per iteration in the authors' cloud, so about 5-7 hours at home.

**Not checked before the run:** whether the model keeps learning up to 100,000 iterations without noise. This is
reported afterwards from the trajectory.

## 3. Predictions

**Definitions:** as run 2. "Final" is iteration 100,000. d is PSF-Zero minus Qiskit, per seed.

**The test:** exact one-sided sign-flip test over the 32 sign patterns of 5 seeds, at alpha = 0.05. To be confirmed,
d must be positive in essentially every seed.

| ID | prediction | confirmed if | refuted if | basis |
|---|---|---|---|---|
| N1 | every arm run valid and complete | all 10 | any not | runs 1 and 2: 440 of 440 |
| N2 | **(primary)** the noiseless final accuracy is higher with PSF-Zero | mean d > 0 and p <= 0.05 | mean d <= 0 | run 1 at 60 iterations: +0.040 (twice); run 2 at 200: -0.000 |
| N3 | the noisy final accuracy is higher with PSF-Zero | as N2 | as N2 | +0.078 / +0.039 (run 1), +0.001 (run 2) |
| N4 | the noisy final margin is higher with PSF-Zero | as N2 | as N2 | 1.32 x in run 2 |
| N5 | **the noiseless difference grows from iteration 60 to 100,000** | mean of (d_final - d_60) > 0 and p <= 0.05 | mean <= 0 | none: this is the question |
| N6 | PSF-Zero spends no more than Qiskit | every seed | any seed over | the same circuits and shots, shorter circuits |

A value between the thresholds is NOT DECIDED.

## 4. Reported without prediction

- The trajectory: the mean difference and each seed's difference at every evaluation point.
- The final figures per arm, and the classical reference.

## 5. How it is read

- **Display:** the final noisy accuracy of each arm.
- **Essential:** each seed's curve of d against iterations. With 5 seeds the statistics are weak; the shape of five
  curves is the result.
- **The money it stands for:** 100,000 iterations on hardware would cost about $380,000 per model at the assumed
  price. This is an experiment on the device model, not a training anyone would run on hardware.
- **Scope:** one task and one device model, in simulation.
