## Question

psf-os `psf_os/twin.py` builds, from each compiled user circuit, its Clifford twin: every RZ angle rounded to the
nearest multiple of pi/2, CZ / SX / X and their order kept, so the same physical pulses (RZ is virtual on Heron). The
twin's answer is exact at any size. On one device-day, does the device keep the same share of the twin's pattern as
of the user circuit's: r_twin against r (r = sum z e / sum e^2 over the chain qubits)?

## Circuits (configurations that have read before)

Two jobs, built with the twin option (`user2d.build_batch(..., twin=True)`; each user circuit gets floor, mirror and
twin; one ring sentinel per job; 4000 shots):
- **XX**: `gpu/ffxx91.py DEV OUT ANS --thetas 0.7853981633974483 --steps 4,8,12 --twin --sentinel-fallback same_qubits` (91 qubits; r on 11-12 fez
  0.68 / 0.50 / 0.33).
- **Hubbard**: `gpu/hub_build.py DEV OUT results/hubbard-2026-11-11/answers/hub_answers_home.json ANS --L 20
  --steps 2 4 6 --arms U4 --twin --sentinel-fallback same_qubits` (40 qubits, U 4; r on 11-11 fez 0.84 / 0.75 / 0.42).
Try-builds on the 15:33 CET 11-12 fez record: 16 circuits and 20.9 s by the model each (41.8 s together); CZ 720 /
1440 / 2160 (XX) and 384 / 768 / 1152 (Hubbard), each twin with the same CZ; circuits_sha256 28163dcd... (XX) and
a2922e31... (Hubbard), recorded in `notes/twin_2026-11-13/trybuild/`; twin answers bdd36d09... / af8f7cf5....

Device: in the order of fewest pending (ties marrakesh, fez, kingston), the first on which both jobs build (both on the
same device). Both builds use the sentinel fallback of 11-13 (`--sentinel-fallback same_qubits`; owner 11:25 JST "OK"):

The quirk ledger (`notes/quirk_ledger_2026-11-13`) is not used for this placement: the run repeats the placements that

## Pre-run check (before submission)

- Twins (`gpu/twin_check.py OUT ANS_twin.json`): the same non-RZ schedule as the user circuit, every RZ a multiple of
  pi/2, and per-qubit <Z> by Aer's stabilizer method equal to the twin answers (worst < 1e-9). Try-builds: ALL PASS
  (worst 0) for both jobs; the assembled jobs carry the twins exactly as built.
- User circuits (`gpu/hub_check.py`): XX at 4 steps and Hubbard at 2 and 4 steps by Aer MPS, Hubbard at 6 steps by
  quimb, against the answers within 1e-6, mirrors back to all zeros. Try-builds: ALL PASS (XX 4 steps worst 4.6e-11;
  Hubbard 2 / 4 / 6 steps worst 9.4e-11 / 2.3e-8 / 1.3e-14; mirrors at most 1.0e-12), in `notes/twin_2026-11-13/trybuild/`.
A job built from the fresh record with the same circuits_sha256 as a checked try-build carries its PASS; otherwise both
checks run on the new build before submission. FAIL anywhere: not run.

## Verdicts (`gpu/twin_score.py OUT USER_ANS TWIN_ANS`)

Per pair: user circuit and twin, each MSE / mean square, READS (<= 1/2), AGREES (0.05), and r; the difference
r_twin - r; and whether r_twin >= 1 - 1/sqrt(2) = 0.293 matches the user circuit's READS. Beside: floor, mirror,
sentinel, CZ.

## Prediction (before any data; not rewritten if wrong)

- |r_twin - r| <= 0.05 for the three XX pairs and for Hubbard at 2 and 4 steps.
- Hubbard at 6 steps: open (its residual was as large as its shrink on 11-11).
- r_twin >= 0.293 matches the user circuit's READS in at least 5 of the 6 pairs.

## Limits

One device-day; the twin sees the multiplicative part of the error only; coherent errors that depend on the RZ angles
can differ between twin and user circuit; the twin's output is a computational basis state with about half the qubits
in 1, while the user circuit's output is not.
